# SkellyEyeSpy

Animatronic Halloween skeleton control, plus an offline pirate photo booth,
built around a Radxa Zero 3W. Background and wiring:
[Radxa Zero 3W-Powered AI Halloween Skeleton](https://hackersvanguard.com/radxa-zero-3w-powered-ai-halloween-skeleton/),
[giving Skelly a voice with the MAX98357A](https://hackersvanguard.com/max98357a-for-radza-zero-3-giving-skelly-a-voice-with-i2s-and-gpio/),
and last year's lessons in
[Overwhelming Animatronics Powered by Local VLM](https://hackersvanguard.com/overwhelming-animatronics-powered-by-local-vlm/).

`app.py` is the base animatronic control server: a Flask app with a browser
dashboard (`templates/dashboard.html`) that drives the mouth, eye and body
motor lines through `skelly/hardware.py` (python-periphery on the board, a
simulated backend on a dev machine, so it also runs on a laptop). It also
registers the photo booth routes when the booth dependencies are installed.

## Pirate Photo Booth (branch: `Pirate-Photo-Booth`)

A visitor steps up, gets a countdown, and the skelly prints a small black and
white souvenir: either a single photo or a tall old-school photo reel of the
visitor cut out of the camera frame and placed on a different pirate scene in
each frame. Everything runs on the board, with no cloud and no GPU: a 250 KB
MediaPipe selfie segmentation model on the CPU, a little compositing, and a
Phomemo M02 thermal printer over Bluetooth.

Design, measurements and status: `docs/photobooth-architecture.md`. Camera,
printer and on-device findings: `docs/hardware-research.md`.

### Setup

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt   # .venv/bin/pip on Linux
.venv/Scripts/python scripts/download_models.py  # fetches the segmentation model
```

`numpy` is pinned to a tested range in `requirements.txt` (the board runs
2.4.6). The background images are not generated by the code: put `.jpg`/`.png`
scenes (roughly 4:3 works best) in `assets/backgrounds/highres/`.

### Run the studio

```bash
# laptop: uses the default webcam and writes a dry-run print file instead of printing
.venv/Scripts/python scripts/run_booth.py configs/dev_laptop.yaml
```

Then open **http://localhost:5001/photobooth/view**. On the skelly, run the same
script with a board config (`configs/skelly_zero3w.yaml` is the template: set
the webcam path, ideally the stable `/dev/v4l/by-id/...` one, and the printer's
Bluetooth address) and open `http://<skelly address>:5001/photobooth/view`
from any machine on the network. The page has **no authentication**, so run it
only on a network you trust.

### Using the studio (preview, tweak, then print)

The page opens in **studio** mode. Nothing prints until you press the print
button.

1. Stand in view of the camera. The live aim view tints the detected people
   green, shows how many it sees (and any tiny distant bystanders it will
   ignore), and shows a preview of the next shot beside it.
2. Press **Start countdown**. It beeps down, then takes one photo.
3. The reel appears in color next to the exact 1-bit image the printer will
   produce, with a thumbnail per frame. Change anything and it re-renders in
   about a second using the same photo.
4. Press **Print this reel**. It prints exactly what is on screen and does not
   take a new photo. **Retake photo** goes back to the live view.

What you can adjust, and the defaults (all tuned by eye on the real printer):

| Control | What it does | Default |
|---|---|---|
| frames | Frames in the reel (1 to 6) | 4 |
| person size | The person's visible height as a share of each frame | 35% |
| stand | Where they stand: center, left, right, alternate, random | alternate |
| edge, edge width, edge strength | How the person is separated from a busy scene: `stipple` (a fading scatter of dots), `separate` (a soft dodge and burn), `none`, `ring` (a solid halo that prints as a glow; kept for comparison) | stipple, 5 px, 30% |
| pop | A little extra saturation and contrast on the person | 15% |
| soften | Calms and brightens the background so it dithers better | 33% |
| morph | Share of frames that blend two scenes | 33% |
| old-timey grain/sepia | Sepia, vignette and film grain on top | on |

Each reel gets a random **seed** (shown under the reel). The backgrounds,
their order, and the per-frame zoom, mirroring and tone shifts all come from it,
so a reel you like can be reproduced with **Use seed**. **Shuffle all** draws a
fresh reel, and **reroll frame N** replaces just one frame's background.
Slider settings stick between renders.

The other modes (reel from one shot, reel with a shot per frame, single photo)
skip the preview and print right after the countdown.

### Backgrounds

`compose.backgrounds` in the config is a glob, so adding art is just dropping
files into the folder. Backgrounds with readable lettering must never be
mirrored: list a distinguishing part of their filename in `compose.no_flip_markers`.
Every setting in the table above also has a config key under `compose:`; see
the comments in `configs/dev_laptop.yaml`.

### HTTP API (what the page uses)

`POST /api/photobooth/draft/capture`, `/draft/render` (query: `shots`, `seed`,
`reroll`, `reroll_all`, `size`, `edge`, `outline`, `strength`, `pop`, `soften`,
`morph`, `anchor`, `vintage`), `/draft/print`; images at
`GET /api/photobooth/draft/image/<strip|print|shot_N>`; plus the direct modes
`/snap`, `/strip/oneshot`, `/strip/start|shot|finish`, and the live view at
`GET /api/photobooth/aim`.

### Dev-loop smoke test and tests

```bash
.venv/Scripts/python scripts/capture_test.py configs/dev_laptop.yaml
.venv/Scripts/python -m pytest tests/
```

The tests need no camera, printer or GPIO. Seeds reproduce the look of a reel,
not bit-exact pixels, so image comparisons in the tests use a small tolerance.

### Known limits

The paced printing for long reels is implemented but has not yet been confirmed
on a complete 4-frame print. People who touch merge into one blob, and the live
test with several people, kids and props is still to do. Photos are kept under
`scratch/booth/` on whatever machine runs the booth. See the next steps in
`docs/photobooth-architecture.md`.
